# Lecture Bot Development Guidelines

## Project Structure
- `app/` - Main application code (FastAPI server)
- `scripts/` - Build and conversion scripts
- `lectures/` - Lecture content packages
- `data/` - Database and generated files
- `tests/` - Test suite

## Import Style Convention

**IMPORTANT: Always use `import module as m` syntax, never `from module import function`**

### Why This Style?
- Makes it immediately clear which module each function/class comes from
- Easier to track and follow dependencies
- Reduces naming ambiguities
- Consistent with the principle of explicit is better than implicit

### Correct Examples
```python
# ✅ CORRECT
import json as j
import pathlib as pathlib_

import fastapi as fa
import pydantic as pd
import sqlalchemy as sa
import sqlalchemy.orm as sqlalchemy_orm

import app.models as models
import app.config as config_module
import app.db as db_module

# Usage
config = j.loads(text)
path = pathlib_.Path("data.txt")
app = fa.FastAPI()
session = sqlalchemy_orm.Session()
```

### Incorrect Examples
```python
# ❌ WRONG - Never use these patterns
from json import loads
from pathlib import Path
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field
from app.models import SessionModel
from app.config import get_settings

# These create ambiguity about where functions come from
```

### Alias Naming Conventions
- Standard library modules: Use short abbreviations or descriptive names
  - `json` → `j`
  - `sys` → `sys_module`
  - `pathlib` → `pathlib_`
  - `functools` → `functools_`
  - `dataclasses` → `dc`

- Third-party packages: Use descriptive names
  - `fastapi` → `fa`
  - `pydantic` → `pd`
  - `sqlalchemy` → `sa`
  - `sqlalchemy.orm` → `sqlalchemy_orm`
  - `pptx` → `pptx_module`

- Local application modules: Use the module name or purpose
  - `app.models` → `models`
  - `app.config` → `config_module`
  - `app.db` → `db_module`
  - `scripts.convert_ipynb_to_md` → `convert_ipynb`

## Running the Application

### Initialize Database
```bash
python scripts/init_db.py
```

### Start Server
```bash
python -m uvicorn app.main:app --reload
```

### Build Lecture Packages
```bash
python scripts/build_lecture_package.py lecture_01
```

## Testing
```bash
pytest tests/
```

## Code Quality
- All Python files must follow the import style convention
- Use type hints for function parameters and return values
- Document public functions and classes with docstrings

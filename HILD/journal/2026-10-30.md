## Session 1 — Making scope issue #40 traceable; are the HILD skills clear on this?

**Goal:** The researcher could not follow [PR #41](https://github.com/opherdonchin/lecture-bot/pull/41) from its documents: who decides what a lecture package contains, what the code checks, and where earlier decisions were made. The researcher's direction: a scope document must link to the decisions and specifications it relies on, must not assume the researcher remembers earlier decisions, and must let the researcher trace those paths and find explanatory material in the wiki.

**Done:**

- Wrote the wiki page [Concept-lecture-package](https://github.com/opherdonchin/lecture-bot/wiki/Concept-lecture-package) (`draft`), which also covers the lecture brief page that [PR #32](https://github.com/opherdonchin/lecture-bot/pull/32) proposed and nobody wrote.

- Corrected the *Wiki pages* section of [PR #41](https://github.com/opherdonchin/lecture-bot/pull/41), described under *Findings*.

**Findings:**

- **Lecture-bot's code does not judge package content.** The loader checks only that files exist; `check-lecture` adds the topic headings and Importance lines. The researcher's review is the only check on content. No record stated this.
- **Importance has no effect.** The app parses it and uses it for nothing: [sampling is random](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/app/bot_engine.py#L431-L436) and the [grade takes the best four topics](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/docs/grading_policy.md#L45-L47). The PML prompt does not mention it.
- **The admin page treats an agent-prepared lecture as stuck.** Run locally, [`current_step`](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/app/admin_workflow.py#L242) gives `select_sources` for L02, since the page follows the Statistics pipeline.
- **The recipe allows 8 topics, and PML's example settings sample 7 per session**, so an eighth topic could push out a load-bearing one at random. L02 has 7. An attempt to read the server's value was denied by the permission system and not retried, so the example's value is unconfirmed for production.
- **My error:** PR #41 said the wiki had "four concept drafts and a scripts guide", none relevant. The [Status board](https://github.com/opherdonchin/lecture-bot/wiki/Status-board) had seven concept pages and two others, eight of them `understood`, and [Concept-course-instance](https://github.com/opherdonchin/lecture-bot/wiki/Concept-course-instance) is directly relevant. The section is corrected.
- **The local instance folder has no history.** `~/lecture-bot-instances` is not in Git, so the recipe and L02's brief are unversioned.

## Session 2 — Process PR, upstream issue, and aligning the prompt with the package

**Goal:** Carry out the agreed process fix, and settle how an agent preparing a package outside lecture-bot knows what the tutor prompt expects.

**Done:**

- Opened [PR #42](https://github.com/opherdonchin/lecture-bot/pull/42), the process rule that a document stands alone (read track). It is a draft: the permission system blocked marking it ready, so the researcher must do that.
- Opened [HILD issue #15](https://github.com/Motor-Learning-Lab/HILD/issues/15) with the same suggestion, at the researcher's request.

**Decisions by the researcher:**

- The code need not check package content.
- **The condition that matters:** the prompt must be aligned with the package it will receive. If local agents generate packages, they need a way to know what is expected.
- The researcher is not yet sure about the changes listed under Session 1's open questions. Settling this comes before proceeding.

**Findings:**

- **Backend and prompt are tied together; prompt and package are not.** Each prompt declares [`Backend contract: 0.6.1`](https://github.com/opherdonchin/lecture-bot/blob/fc5faec2ba97d0a22940d7995280ee9d558cf3b0/prompts/pml_tutor_prompt.md#L1), and the backend [refuses a mismatch](https://github.com/opherdonchin/lecture-bot/blob/fc5faec2ba97d0a22940d7995280ee9d558cf3b0/app/prompt_loader.py#L76-L81) ([PR #38](https://github.com/opherdonchin/lecture-bot/pull/38)). The prompt [describes what it expects of a brief in prose](https://github.com/opherdonchin/lecture-bot/blob/fc5faec2ba97d0a22940d7995280ee9d558cf3b0/prompts/pml_tutor_prompt.md#L8) and names no format. The [format document](https://github.com/opherdonchin/lecture-bot/blob/fc5faec2ba97d0a22940d7995280ee9d558cf3b0/docs/lecture_brief_format.md) names the prompt, but nothing ties them together or detects a package built for an older format.
- **In [PR #41](https://github.com/opherdonchin/lecture-bot/pull/41), an agent reaches the format only through the private recipe.** The skill sends it to the recipe, and the recipe names the format document. The public process therefore depends on a private file saying the right thing.
- **L02 matches the current format's sections.** A count of its seven topics found *Teach*, *Assess*, each evidence level, depth, good moves and scoring cues in each, and *Across topics*. This counts sections and does not judge them. One small difference: L01 and L02 both label evidence `**Strong:**`, `**Partial:**` and `**Weak:**`, where the format document says `**Strong evidence:**` and so on. The prompt understands either, but it is a small example of the format and the packages drifting with nothing to notice it.

**Proposal, not started, waiting on the researcher:**

1. The expected package is described by a file beside the prompt, named after it, as the [private-artifact schema already is](https://github.com/opherdonchin/lecture-bot/blob/fc5faec2ba97d0a22940d7995280ee9d558cf3b0/prompts/pml_tutor_prompt_private_artifact_schema.json). It carries a format version, and changes in the same PR as the prompt.
2. The `prepare-lecture` skill finds the course's prompt from its [instance settings](https://github.com/opherdonchin/lecture-bot/blob/fc5faec2ba97d0a22940d7995280ee9d558cf3b0/deploy/instances/pml.env.example#L42) and reads that file. The recipe keeps only sources and emphases.
3. The package's config records the format version it was built for, and `check-lecture` fails on a mismatch. No check at run time, which could take a live lecture down when a prompt changes.
4. The format lists only what the prompt or the backend actually uses. That would settle Importance (drop it) and the topic cap (no more than `SAMPLED_TOPIC_COUNT`).

**Limit of this proposal:** it catches a package built for an old format. It cannot show that the format file matches what the prompt actually does; that stays with review of the PR changing them.

**Open questions / next:** the researcher's answer on this proposal; then decision record 0002, an amendment to [scope issue #40](https://github.com/opherdonchin/lecture-bot/issues/40), and the rewrite of PR #41's explanation.

# 2026-10-30

## Session 1 — Making scope issue #40 traceable; are the HILD skills clear on this?

**Goal:** The researcher could not follow [PR #41](https://github.com/opherdonchin/lecture-bot/pull/41) from its documents: who decides what a lecture package contains, what the code checks, and where earlier decisions were made. The researcher's direction: a scope document must link to the decisions and specifications it relies on, must not assume the researcher remembers earlier decisions, and must let the researcher trace those paths and find explanatory material in the wiki.

**Done:**

- Wrote the wiki page [Concept-lecture-package](https://github.com/opherdonchin/lecture-bot/wiki/Concept-lecture-package) (`draft`), which also covers the lecture brief page that [PR #32](https://github.com/opherdonchin/lecture-bot/pull/32) proposed and nobody wrote.
- Edited [scope issue #40](https://github.com/opherdonchin/lecture-bot/issues/40) to add what it rests on, links and the open questions below. What it authorizes did not change.
- Corrected the *Wiki pages* section of [PR #41](https://github.com/opherdonchin/lecture-bot/pull/41), described under *Findings*.

**Findings:**

- **Lecture-bot's code does not judge package content.** The loader checks only that files exist; `check-lecture` adds the topic headings and Importance lines. The researcher's review is the only check on content. No record stated this.
- **Importance has no effect.** The app parses it and uses it for nothing: [sampling is random](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/app/bot_engine.py#L431-L436) and the [grade takes the best four topics](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/docs/grading_policy.md#L45-L47). The PML prompt does not mention it.
- **The admin page treats an agent-prepared lecture as stuck.** Run locally, [`current_step`](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/app/admin_workflow.py#L242) gives `select_sources` for L02, since the page follows the Statistics pipeline.
- **The recipe allows 8 topics, and PML's example settings sample 7 per session**, so an eighth topic could push out a load-bearing one at random. L02 has 7. An attempt to read the server's value was denied by the permission system and not retried, so the example's value is unconfirmed for production.
- **My error:** PR #41 said the wiki had "four concept drafts and a scripts guide", none relevant. The [Status board](https://github.com/opherdonchin/lecture-bot/wiki/Status-board) had seven concept pages and two others, eight of them `understood`, and [Concept-course-instance](https://github.com/opherdonchin/lecture-bot/wiki/Concept-course-instance) is directly relevant. The section is corrected.
- **The local instance folder has no history.** `~/lecture-bot-instances` is not in Git, so the recipe and L02's brief are unversioned.

**Are the HILD skills clear on tracing decisions? No.** Each gap below was checked against the current text.

- [`HILD/process.md`, Presentations rule 4](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/HILD/process.md#L216) requires links for claims, but most of it concerns link mechanics. Nothing says a document must not assume the reader remembers an earlier decision.
- [Rule 10](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/HILD/process.md#L262) requires a wiki section in every *explanation*, not in a proposal.
- [`hild-scope`](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/.agents/skills/hild-scope/SKILL.md) tells the agent to read relevant decisions but not to cite them. It says nothing about the wiki or about links, except the link to the issue.
- The [scope issue template](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/HILD/templates/scope-issue.md) has no place for what a scope rests on or for wiki pages.
- [`hild-explain`](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/.agents/skills/hild-explain/SKILL.md) and the [PR template](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/HILD/templates/pr-explanation.md) cover code permalinks and the wiki, but not the decisions and specifications behind a change.
- **Decision records are skipped in practice.** [`hild-journal`](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/.agents/skills/hild-journal/SKILL.md) step 3 says to record important decisions separately, but [only decision 0001 exists](https://github.com/opherdonchin/lecture-bot/tree/40eea206f12a07a5b72c5b0a21810c85f16dccce/HILD/decisions). Later consequential choices are only in scope issues, PRs and the journal, so a trace has to go through those.
- **Proposed wiki pages get lost.** A page proposed in a PR is tracked nowhere once the PR merges: the Status board's `not-written` list covers only pages that another wiki page links to. [`hild-digest`](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/.agents/skills/hild-digest/SKILL.md) does not check for them either.

[`hild-orient`](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/.agents/skills/hild-orient/SKILL.md) and [`hild-understood`](https://github.com/opherdonchin/lecture-bot/blob/40eea206f12a07a5b72c5b0a21810c85f16dccce/.agents/skills/hild-understood/SKILL.md) need no change for this; they already ask for links.

**Proposed fix, not started:** one read-track PR with a new Presentations rule (a document stands alone: it names each earlier decision or specification it relies on, links where it was decided, specified and explained, and says when no record exists), a *What this rests on* section in the scope and PR templates, one line each in `hild-scope` and `hild-explain` pointing to the rule, and a `hild-digest` check for proposed pages that were never written. It needs the researcher's approval, because process changes are the researcher's to accept.

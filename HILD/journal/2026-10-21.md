**Findings:**

  draft PRs ([#11](https://github.com/Motor-Learning-Lab/HILD/pull/11),

  repository with `--delete`, which conflicts with the repository being
  authoritative. It was not used for today's copy.

  `.log`, `.pdf`), owned by root and dated 2026-10-20, sit in the server's
  `/srv`. They were reported to the researcher and not investigated further.

**Decisions:** An independent HILD build rather than an install
([decision 0001](../decisions/0001-independent-hild-build.md), proposed).
Pin HILD at `92de97e`. Enable Claude Code and Codex hooks, but not Copilot.
Keep `prompts/archive/` and `docs/archive/` as deliberate history.

## Session 2 — Scope approvals, course-sources redesign, PR 2a

**Goal:** Get the scopes for the PML instance and the L01 package agreed, and
start PR 2a (the PML instance) under
[#16](https://github.com/opherdonchin/lecture-bot/issues/16).

**Done:**

- **Hook verified:** this session's orientation was built from the
  session-start hook's output, so the Claude Code hook is *executed and used*.
- The researcher approved [#16](https://github.com/opherdonchin/lecture-bot/issues/16)
  in chat; [recorded on the issue](https://github.com/opherdonchin/lecture-bot/issues/16#issuecomment-6310738318).
- The researcher found #17 unclear and asked for a course-independent way to
  handle uploads. The agreed design: courses declare their sources (required
  or optional, formats, role) in the instance's `lectures/config.json`, and
  lecture-bot provides a modest converter family (PowerPoint, Word, PDF, VTT,
  HTML, plus existing ones). Courses convert any other format themselves.
  This became [#18](https://github.com/opherdonchin/lecture-bot/issues/18),
  approved in chat and [recorded](https://github.com/opherdonchin/lecture-bot/issues/18#issuecomment-6320392819).
- [#17](https://github.com/opherdonchin/lecture-bot/issues/17) was rewritten
  to cover only the hand-built L01 package (plus an L02 fallback). At the
  researcher's request it was amended to add a review of the tutor prompt for
  PML, without prompt changes ([comment](https://github.com/opherdonchin/lecture-bot/issues/17#issuecomment-6322020281)).
  It awaits approval.
- PR 2a on `deploy/pml-instance`:
  [8fe2c9f](https://github.com/opherdonchin/lecture-bot/commit/8fe2c9f)
  (template units, nginx and PML env examples, with a test that the env

  [b49aff4](https://github.com/opherdonchin/lecture-bot/commit/b49aff4)
  (admin page shows the instance's own restart command),
  [01d874b](https://github.com/opherdonchin/lecture-bot/commit/01d874b)

  passed. A dry run of the new `publish-prod` against the server reported

  on the server and changed nothing else.

**Findings:**

- The old `publish-prod` rsynced the local tree with `--delete` and did not
  exclude `lectures/`. From this clone (lectures 01–09) it would have deleted
  server lectures 10–12 and server-only files (`reports/`, `presentations/`,
  a PDF and a spreadsheet). It was not run.
- The server checkout's reflog shows only commits made in place (2026-06-04
  to 2026-07-26) and no pulls: production was developed on the server.
- The deploy account has no passwordless sudo, and its non-interactive PATH
  lacks Pixi (`~/.pixi/bin/pixi` works).
- The live nginx config sets `client_max_body_size 250m` on the admin
  location only; the nginx example matches it.
- Activating a tutor prompt from an admin app rewrites the shared `prompts/`
  files, so one instance's admin can change every course's tutor. Noted for
  PR 2b.

**Decisions:** Deploy by fast-forwarding the server checkout to
`origin/main` instead of rsync, chosen as the light version of standard
practice after the researcher asked for reasonable hygiene without
over-engineering; reviewed in PR 2a.

**Permission points:** Replacing the rsync publish goes beyond #16's
explicit list. The researcher was told before the work and asked for a
recommendation; the choice is presented for full-track review in PR 2a.
